本网站开发过程 / DEV PROCESS

以下是 Y2K 个人星球网站从需求到交付的完整开发过程总结，涵盖需求定义、原型设计、提示词策略、版本迭代记录与问题解决过程。完整文档请见底部附录。

1. 需求 / REQUIREMENTS

  • 以 Y2K 美学为核心的单页应用个人网站，纯前端实现（HTML5 + CSS3 + JS + Canvas + Three.js）
  • 7 个功能页面：首页星球、四向导航、证明记录与复盘、阶段练习与项目成果、个人简介、抽屉收藏盒、过程证据
  • 粉色调配色（#fca5d8 / #ff7ebb / #ffd3ec / #d64082）+ 深紫（#2a1b3d）
  • 英文用 Press Start 2P 字体，中文用 ZhengGeDianHei 16 铁素字体
  • 首页头像点击触发中日韩英四语自我介绍朗读（ElevenLabs 狛枝凪斗音色）
  • 万花筒、水波纹、3D 波浪空间三大创意动效
  • 全站像素渲染（image-rendering: pixelated）

2. 原型 / PROTOTYPE

  • 首页：像素星球居中 + 万花筒背景 + 可点击头像，点击星球触发马赛克过渡
  • 四向导航：水波纹背景 + 上/右/左/下四个像素按钮，分别进入子页面
  • 证明记录与复盘：3D 波浪空间 + 三个浮动像素图标（文件夹/光盘/文档）
  • 阶段练习与项目成果：3D 波浪空间 + 书本陈列，点击展开预览弹窗
  • 个人简介：4:3 复古电脑弹窗（Windows 98 风格），含头像、简介、技能标签
  • 抽屉收藏盒：多层抽屉 + 正方形预览弹窗
  • 过程证据：复用复古弹窗展示开发文档 + 底部附录入口

3. 提示词与对话策略 / PROMPTS

  • 先定调再写码：每次新需求先说明整体风格和约束，再给具体功能点
  • 参数精确化：不说"调慢一点"，说"旋转速度 t*0.02"；不说"大一点"，说"放大到 1.06 倍"
  • 约束前置：字体、配色、端口等约束在第一轮对话中一次性明确
  • 修正隔离：修正某处时明确"不要改动其他部分"，防止 AI 自作主张改动已确认内容
  • 资源指名：图片资源给出确切文件名（bubble.png / mei.png / 背景.png）
  • 状态枚举：交互效果按 hover/click/active/idle 状态逐一描述

4. 版本记录 / VERSIONS

  • v0.1（09-20）：项目骨架 + 页面切换动画（20x20 像素马赛克过渡）
  • v0.2（09-21）：首页星球 + 万花筒背景引擎
  • v0.3（09-22）：四向导航页 + 水波纹可复用引擎
  • v0.4-v0.6（09-22~23）：阶段练习/个人简介/抽屉收藏盒页面
  • v0.7（09-24）：证明记录与复盘页 + 三个图标呼吸浮动
  • v0.8（10-10）：ElevenLabs 四语朗读功能
  • v0.9~v0.9.5（10-11~12）：头像闪白优化、端口修复、字体恢复、page-6 独立、图标统一
  • v1.0（10-12）：新增 page-7 过程证据 + 4 份开发文档

5. 问题与解决 / ISSUES

  • Canvas 0x0：display:none 页面 Canvas 初始尺寸为 0，用 MutationObserver 在可见时重新测量
  • 端口占用：8765 被抢占，切换至 8766
  • 字体丢失：ZhengGeDianHei-16 文件被移至 iCloud 回收站，手动恢复
  • 跳转错误：page-3 BACK 误跳 page-5，修正为返回 page-2
  • 头像脉动：简化为点击瞬间闪白，移除朗读期间脉动呼吸
  • 声线不够：Web Speech API 无法复刻狛枝凪斗，接入 ElevenLabs TTS API
  • API 权限：ElevenLabs Key 未勾选 text_to_speech 权限，重新创建
  • 滚动条不触发：flex 子元素设 min-height:0 限制高度
  • 3D 黑色断裂：墙面尺寸设为 20 + 背景色 0xffd6e8

v0.3 — 2026-09-22 四向导航 + 水波纹引擎

  • 为什么改：水波纹是核心交互特效，需多页面复用，封装函数避免重复代码；z-index:10 确保按钮在重叠元素上方可点击。

最终学习复盘 / FINAL REFLECTION

本网站是我第一次独立完成的完整前端项目，从需求分析到设计落地，从特效实现到问题排查，整个过程让我在技术、设计、思维三个维度都有了显著成长。以下是我对本次项目的全面复盘。

一、技术收获 / TECHNICAL GAINS

  • Canvas 2D 深入掌握：通过万花筒和水波纹两个引擎，深入理解了 Canvas 的像素级操作（getImageData/putImageData）、离屏画布、纹理采样与变形、requestAnimationFrame 动画循环。万花筒的 12 切片对称绘制、水波纹的双缓冲波场计算，让我对 2D 图形渲染有了质的飞跃。
  • Three.js 3D 空间入门：学会了场景/相机/渲染器的基本搭建，ShaderMaterial 自定义着色器实现波浪网格，纹理贴图与 RepeatWrapping 重复平铺，以及页面可见性触发的按需初始化。
  • CSS 工程化实践：用 CSS 变量统一管理配色，用 clamp() 实现响应式尺寸，用 aspect-ratio 固定比例，用 flex 布局 + min-height:0 解决滚动容器问题，用 ::after 伪元素实现发光效果，这些技巧让代码更整洁、可维护性更强。
  • 第三方 API 接入：成功接入 ElevenLabs TTS API，掌握了 fetch + Blob + URL.createObjectURL 的音频播放流程，以及按句拆分 + 缓存的性能优化策略。
  • 可复用函数封装：将水波纹和 3D 空间封装为 createRippleEngine / createSpace3D，多页面共享同一套逻辑，体会到了"DRY 原则"在实际项目中的价值。

二、设计感悟 / DESIGN INSIGHTS

  • 风格统一是灵魂：全站粉色调 + 像素字体 + Windows 98 弹窗的组合，形成了强烈的 Y2K 视觉识别度。每一个细节（边框阴影、按钮按压、滚动条样式）都服务于整体风格，缺一不可。
  • 动效服务于体验：万花筒、水波纹、3D 波浪、呼吸浮动——这些动效不是为了炫技，而是为了营造"星球"的沉浸感和"复古"的怀旧感。动效要克制，过度反而干扰内容。
  • 交互反馈要清晰：hover 放大、点击闪白、按下位移——每一个可交互元素都要有明确的状态反馈，让用户知道"这个能点""点到了"。
  • 字体是气质的关键：Press Start 2P 的英文字体和 ZhengGeDianHei 16 的中文铁素字体，直接决定了网站的"像素复古"气质。选错字体，再好看的配色也救不回来。
  • 自适应不可忽视：clamp()、aspect-ratio、flex-wrap 这些响应式手段，确保了网站在不同屏幕尺寸下都能正常展示，避免了"在我电脑上好好的"的尴尬。

三、问题解决能力 / PROBLEM-SOLVING

  • 从现象到根因：遇到 Canvas 0x0、滚动条不触发、字体回退等问题时，学会了不急于改代码，而是先定位根因（display:none 隐藏、flex min-height:auto、字体文件缺失），再针对性修复。
  • 善用浏览器开发者工具：Console 报错、Network 面板、Elements 实时调试，这些工具让排查效率成倍提升。尤其是 Network 面板，帮助定位了 API 权限不足、字体加载失败等问题。
  • 勇于换方案：当 Web Speech API 无法复刻狛枝凪斗声线时，没有死磕，而是果断切换到 ElevenLabs 方案。技术选型不一定要"最原生"，而是要"最适合"。
  • 记录与回溯：每一个问题都记录在版本记录与问题解决文档中，形成可追溯的知识库。下次遇到类似问题，可以直接查阅，不用重新踩坑。

四、协作与沟通 / COLLABORATION

  • 与 AI 协作的方法论：学会了用精确参数代替模糊描述（"旋转速度 t*0.02"而非"调慢一点"），用约束前置减少返工（字体/配色/端口一次性说清），用"不要改动其他部分"隔离修正范围。
  • 需求表达要结构化：把需求拆成"背景→目标→约束→验收标准"四层，AI 才能准确理解意图，避免南辕北辙。
  • 及时验证不盲信：AI 给出的代码不一定全对，每次修改后都要实际运行验证，遇到"没看见效果"先硬刷新清缓存，再排查代码。

五、不足与改进 / SHORTCOMINGS

  • 缺少代码注释：部分复杂逻辑（如水波纹波场计算、万花筒切片数学）没有写注释，后续维护时需要重新推导。改进：关键算法必须写清思路和公式。
  • 移动端适配不足：目前主要针对桌面端优化，移动端的触摸交互、小屏布局还需要专门适配。改进：增加 touch 事件监听，用 media query 针对小屏调整。
  • 性能优化空间：万花筒和水波纹同时运行时，低端设备可能掉帧。改进：用 Page Visibility API 在页面不可见时暂停动画，降低采样率。
  • 无障碍设计缺失：没有考虑键盘导航、屏幕阅读器、色盲友好等无障碍需求。改进：补充 aria-label、tabindex、焦点样式。
  • 版本管理不规范：没有使用 Git，所有改动都在单文件上直接修改，无法回滚。改进：后续项目必须用 Git 管理，每个版本打 tag。

六、未来规划 / FUTURE PLANS

  • 深化 Canvas 与 WebGL：继续学习 Shader 编程，尝试用 WebGL 实现更复杂的粒子系统和后处理特效，把万花筒和水波纹升级到 GPU 加速。
  • 学习前端框架：下一项目尝试用 Vue 或 React 重构，理解组件化、状态管理、路由等工程化概念，对比原生 JS 的差异。
  • 拓展游戏开发：网站里有多个 IP 二创作品（全职猎人/弹丸论破/银魂），未来想做完整的网页小游戏，加入关卡设计、存档系统、排行榜等。
  • 建立个人作品集：把这个网站作为起点，持续迭代更新，把更多作品和项目加进来，打造一个真正属于自己的"星球"。
  • 保持记录习惯：延续本次项目的文档化习惯，每个项目都写需求文档、迭代记录、问题解决和最终复盘，让成长有迹可循。

结语 / CLOSING

这个网站从一行代码开始，到现在 7 个页面、3 套引擎、4 份文档，每一个像素都是认真攒下的小星星。它不完美，但它是我的。感谢 Y2K 美学给了我灵感，感谢 AI 工具给了我助力，更感谢那个愿意从零开始、一步步把想法变成现实的自己。未来的路还很长，继续在自己的星球上发光吧 ♡
